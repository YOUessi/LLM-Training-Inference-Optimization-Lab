# Stage46 — actual vLLM AWQ/FP16 instruction correctness on the same IFBench60

**Frozen before Stage44 test verdicts are used for model selection:** Qwen3-8B rank16 LoRA was trained under 4-bit NF4 BF16, while the Stage43/45 actual OpenAI-compatible vLLM service loads **Qwen3-8B-AWQ FP16**. It is unknown whether Stage44's independent IFBench NF4/BF16 compliance numbers transfer to AWQ runtime. Stage46 is a *paired quantization/backend compatibility experiment*, not a new heldout model-selection stage, and reuses the **same** fixed IFBench60 external source identities from Stage44 to isolate deployment differences. It does not look at Stage44/46 model scores to adjust Stage42's fixed regex router.

**Real GPU deployment:** Run official frozen vLLM0.19.1 loopback `127.0.0.1:8033`, single engine, `--enable-lora --max-lora-rank16 --lora-modules qwen3-8b-dolly-r16=...`, Qwen3-8B-AWQ original model ID `qwen3-8b-awq-local`, rank16 Stage31 NF4-trained adapter loaded at runtime. Verify `/v1/models` registers both IDs, warm on unrelated short query, then issue identical 60 IFBench prompts ×2 actual model IDs = **120 real HTTP calls**, greedy `temperature=0`, no-thinking, `max_tokens=384`. Actual original prompt text and full generated responses are stored privately on Tang to avoid republising crowd content. Stage42 classifier chooses routed backend from the original prompt before responses are available; its routed answer is exactly the selected actual AWQ model response, not a third unconstrained generated/model-jury candidate. This test is **sequential quality evaluation**, not a serving concurrency/QPS comparison; Stage45 covers actual model route under load.

**Official grading and comparison:** Reuse unchanged official AllenAI IFBench source `evaluation_lib.test_instruction_following_strict/loose`, 83 registered verifiers, genuine SHA-verified NLTK resources. Report per-case exact constraint family pass/fail, strict/loose 60-prompt accuracy, 384-token cap-hit frequencies, route fraction and paired fixed-family bootstrap, source hashes and API model registry. Comparison of Stage44 NF4 vs Stage46 AWQ must use exactly identical source keys, original prompt SHA and selected model roles; quantify discrepancies and **never** claim identical quality if AWQ changes output. No model or router parameters adjusted using either test.

**Blocking gates:** If /health, model registration, source-hash, any of 120 actual API calls, official scoring, or private/public SHA reconciliation fails, mark invalid with raw error and do not substitute offline text. Run source-pinned detached Git worktree under GPU `flock`, no other model server, no overwrite, finite bounded timeout and reliable process cleanup. Any application-safe production claim requires not only on-the-server constraint adherence but also full user-answer quality, independent external multi-language data, concurrency/TTFT and long-duration SLO; current IFBench 60 constrained subset is not production traffic, and severe output truncation can invalidate narrow score comparisons.
