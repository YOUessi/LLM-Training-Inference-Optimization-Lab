# Stage33 59.375-second sustained demand / new prefix cache test

Adds **strictly longer offered windows** to Stage30: 96 **distinct source question IDs** per arm, at 1.6 open-loop requests/s =59.375 seconds of planned arrivals. Qwen3-8B-AWQ real vLLM0.19.1 server, GPU memory util 0.82, max-num-seqs16, loopback-only. Three frozen arrival seeds 3011/3029/3041 × two prefix mixtures (100% cold distinct leading header, 50% shared hot header) × cache OFF/ON, fresh server per arm, 12 cases = **1,152 real offers**. Both cache arms within a seed/mix receive byte-identical requests/arrival offsets and balanced label/detailed output modes. The order of cache arms is reversed for the middle seed to partly mitigate drift. Metrics: all-offered TTFT<=250/500/1000/2000ms, p95/p99, useful output TPS, running/waiting server gauges, KV fraction, short/long output validity, and paired per-seed bootstrap CI. This is *moderate offered rate*, not 8/s overload; it is designed to test whether caching has a benefit after continuous low-to-moderate load, not a system capacity peak. Full provenance as prior Stage30 PSF doc corpus, no new data-source generalization claim.

Source frozen and GPU-lock fail-closed, strict 12-arm completion. No partial or failed case counted. Two stage results together provide 8/s (11.875-second) and 1.6/s (59.375-second) regimes on same frozen sources but differ in load and duration. No claims about hour-scale drift, user-population distribution, or unmeasured cache-hit counters.
