# Stage43: real vLLM single-engine dual Qwen3-8B-AWQ and rank16 LoRA integration

**Preregistered independent of Stage42 test outcomes.** Stage42's prompt-only IFEval base-vs-SFT router is **offline Transformers NF4 evaluation**, not a running vLLM production server. Stage43 separately verifies whether vLLM **0.19.1** on one RTX4090 Laptop 16GB can actually serve Qwen3-8B-AWQ **base plus one rank16 Q/V LoRA** in a *single* local engine. The selected Stage31 rank16 PEFT checkpoint was trained on Qwen3-8B NF4 BF16, while vLLM base is 4-bit AWQ FP16 compute. **AWQ vs NF4 checkpoint quantization is a materially different base regime**: do not transfer Stage42 quality/equivalence claims to vLLM without an independent IFEval correctness study. The Stage43 test's first job is **compatibility, model registry and API correctness**, not a quality or high-load win.

The script starts `vllm serve /home/you/models/Qwen3-8B-AWQ --enable-lora --max-lora-rank 16 --max-loras 1 --lora-dtype float16 --lora-modules qwen3-8b-dolly-r16=<selected-adapter-path>` with `--host 127.0.0.1 --port 8033`, max-model-len2048, max-num-seqs16, GPU memory utilization .82 and prefix caching disabled to avoid conflating adapter overhead with warm KV reuse. Verify /health and `/v1/models` actually lists both base `qwen3-8b-awq-local` and LoRA `qwen3-8b-dolly-r16`. Then issue **72 real GPU requests** over 24 fixed, unique PSF-documented technical questions: base, LoRA and deterministic prompt-only router (same source prompt under all conditions, no eval labels). Each short `max_tokens=64` response must complete without API error, record request ID/hash/served model, TTFT, latency and actual output tokens. Model-server memory snapshot and logs retained. Zero invented times or offline simulations; no other GPU process allowed, exact source SHA and shared `flock` locks, finite 500-second client timeout, no-overwrite, reliable graceful cleanup. Negative compatibility failures are retained, not silently converted to an application speed improvement.

**Important limits:** 24 PSF prompts and 64-token output cap, sequential API requests for functional compatibility rather than concurrency/saturation, no independent human task correctness. Adapter trained on a different base quantization; quality can shift. Actual production request classifier/fanout and multi-LoRA service still require independent completed measured cold/hot load test, typed errors, reliable rollback and security validation. This is a system integration milestone, not a full release permit.
