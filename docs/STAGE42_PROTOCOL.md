# Stage42 — prompt-only constraint-aware base vs SFT routing, clean frozen source identities

**Pre-run hypothesis, NOT a measured claim:** Pure Dolly assistant-CE optimization demonstrably reduced Google official IFEval strict obedience; LoRA α=.75 only partially recovered (unseen101 α=.75 67/101 vs original base78/101), deterministic JSON/XML/start-end format rehearsal SFT trained 6 full 8B models and failed every strict-dev guard. A safe infrastructure-level response can dynamically use original Qwen3-8B for explicitly hard-constrained human instructions while retaining the specialized Stage31 rank16 QLoRA for ordinary question-answer requests. This is prompt-conditioned expert routing, not a newly trained model.

**Strict zero-test-selection:** Freeze `stage42_risk_router.choose_model(prompt)` before evaluation, with only portable user-language regex features: exact counts, output format JSON/XML/markdown, start/end markers, punctuation/token counts, exclusions (`without`/`do not`), explicit requirements (`must`), etc. A deterministic risk score (threshold 2) chooses **base** for explicit hard constraints; otherwise **LoRA SFT**. No IFEval key, original reference answer, official checker result, benchmark family, source dataset name, or generated model output is an input to the router. One response from the selected model only in actual deployment; for evaluation both base and LoRA produce paired counterfactual responses so the exact true baselines are auditable. Per-item chosen-model inference cost equals the corresponding candidate generation, not both.

**Data provenance:** From 541 official Google IFEval Apache-2.0 prompts, EXCLUDE all **325 previously examined IDs** (Stage36 96, Stage38 dev43/test101, Stage40 dev25/test60) and apply the earlier frozen feasibility rules before SHA256 stratified selection of **96 never-before-tested instructions** across nine source instruction families (fixed category quotas). No category or verifier result is presented to the route. A second **128 disjoint Dolly15k (CC BY-SA 3.0) human instruction/answer source records**, 16 per category, is drawn after excluding all **960 previously examined IDs** (704 initial train/val/test, 128 Stage34, 128 Stage41), full assistant chat <=384 tokens. Both sources are public and could be in Qwen3 original pretraining; record identities are independent within source, not independent dataset distributions.

**Comparisons and outcome gates:** Use original Qwen3-8B NF4 base and existing validation-selected Stage31 full512 rank16 Q/V LoRA with exactly the same greedy non-thinking chat encoding. On new IFEval96 generate both outputs (384 max) and evaluate original Google strict/loose prompt and instruction-level rule compliance; routed output is selected deterministically from precomputed generated candidates only, **before official grading**. On new Dolly128 compute answer-only token-weighted CE under base, full LoRA, and routed-by-request variants, with identical masked token labels. Report source-type conditional counts, error categories, 384-token truncation rates, P95 generation latency, and three-arm paired stratified fixed-sample bootstrap intervals. No test-guided parameter changes allowed. **Research-level joint gate:** router strict IFEval correct count >= original base count−2 *and* routed Dolly CE >=0.50 nats/token better than base. The gate was written before any Stage42 model output. If either fails, report failure and do not tune on these test IDs.

**Limitations and production:** This is a simple **handcrafted deterministic routing baseline**, not a learned novel algorithm or proof that the original model is truly safer/better on all hard constraints. Explicit IFEval prompts make the dispatch particularly simple; future actual mixed user traffic can contain implicit, bilingual or complex constraints, and naive lexical router may miss them. A base fallback can improve rule-following while sacrificing domain-specific task accuracy, so report both. Actual low-level serving implementation requires vLLM multi-LoRA and separate quality/latency tests, and end-to-end production SLA is not established by offline paired generation. Source-pinned real GPU on Tang under shared mutex, no concurrent vLLM server, finite timeouts, exact hash and per-item accountability, no cherry-picking of later benchmark cases.
