# Stage45 — real concurrent vLLM AWQ+LoRA request routing with OASST user prompts

**Preregistered before experiment:** Stage43 verified vLLM 0.19.1 single-engine actual Qwen3-8B-AWQ base + rank16 Stage31 LoRA are available via OpenAI API with 72 sequential successful requests. Stage45 verifies *actual routed* concurrent scheduling and throughput on same GPU, using the original public OASST1 human prompter inputs (same source originally Stage35, Apache-2.0), while keeping user prompt text local only. No benchmark label/response data influences router model selection. Original Qwen3-8B-AWQ vs NF4 8B training-base quantization mismatch remains a reason to **independently evaluate quality on AWQ**; this is a serving system test only.

Input: 72 **unique** OASST1 source messages frozen before requests, exactly 24 per original English, Spanish and Chinese communities, chosen from prefiltered 32 per language using a stable SHA rank (not model outcomes). Two independent arrival seeds (4511,4527) only change arrival order, not chosen IDs. Fixed offer window with **4/s and 8/s**, three serving policies: always base model ID, always LoRA model ID, or existing Stage42 *prompt-only* hard-constraint classifier `choose_model(prompt)` selecting one model ID. Exactly 2 seeds ×2 rates ×3 policies=**12 real server arms**, 72 offered each, total **864 actual generated API responses**. Each arm starts a **fresh** vLLM dual-model server on `127.0.0.1:8033`, max-num-seqs16, GPU util.82, **no prefix caching** to isolate adapter/selection overhead, warms both actual endpoints with an unrelated 20-token request (excluded from measurements), then open-loop submits each original user message with no per-request task-id, max192 decoded tokens and non-thinking. Only the selected single backend is called in a routed request (not speculative double generation). Server process ends before next arm; counterbalance policy order in second seed.

Metrics: all-offered 250/500/1000/2000ms TTFT from scheduled request time including executor wait, P95/P99, useful decoded output tokens/s, actual rejected/errors, per-language completion/cap hits, router model-share, real server waiting/running gauges and KV utilization from Prometheus, output cap192 hit fraction. All full original user prompt text is omitted from GitHub JSON; only IDs, SHA, language and numeric metrics remain. No partial arm accepted; shared GPU `flock` and no preexisting process/port, frozen SHA, bounded per-arm completion, graceful server cleanup, no overwrite. Model registry must show both base and LoRA before each arm.

**Not a production authorization:** Only two arrival seeds, 72 individual source prompts per arm with artificial language balance, 192 max output tokens may truncate answers (report actual cap), 4/s and8/s short bursts; fresh server restarts may add run-order drift; AWQ base differs from NF4/BF16 model used to establish IFEval quality, and the same user prompts were already used for serving Stage35/37, though not for training. A good routed TPS/TTFT does NOT prove user-answer instruction obedience, safety, or model quality without external AWQ-vs-NF4 IFEval and real traffic load. Any broken LoRA handling or GPU fault invalidates the affected arm, never replaced with simulated completions.
