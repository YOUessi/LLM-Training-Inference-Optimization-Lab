# Stage38: recover instruction adherence with guarded Qwen3-8B LoRA strength (pre-frozen)

**Why now:** Independent Google IFEval Stage36 showed serious capability regression despite Dolly answer-likelihood gains: original Qwen3-8B 73.96% strict obedience, Stage26 short QLoRA 44.79%, Stage31 best full512 QLoRA 54.17% on the pre-frozen 96-example IFEval subset. Treat this as a *strong negative result* requiring better multiobjective training/inference evaluation, not a new model success. Full QLoRA was selected on Dolly validation before IFEval; Stage36 is now **observed and not reusable as a new holdout**.

**Split and leakage gate:** From the original 541 official Google IFEval records, SHA verified, **exclude all Stage36 96 evaluated identities entirely**. Apply the same original fixed feasibility filters as Stage36, then freeze an SHA-selected, nine-family stratified **43-example dev** + **101-example strictly unseen final IFEval test** with no identity overlap. Per-class fixed 5 dev +12 test except language3+5 due data scarcity. Original IFEval sources Apache-2.0, official Google rule-check evaluator pinned at `7e672cc`. No model outputs ever consulted to choose the split.

**Experiment:** Load existing Stage31 rank16 seed3127 QLoRA (no further SFT retraining), evaluate **LoRA residual scaling** α ∈ {0,0.25,0.5,0.75,1.0}; α=0 is original base with adapter disabled, α=1 original Stage31 adapter. All 72 LoRA q/v layers multiply their original PEFT scaling constants by α only within a context manager and **restore them after each run**. Same 43 IFEval dev prompts at greedy `max_new_tokens=384`, no thinking, all scored by unchanged Google strict/loose rule checkers; **separately**, all 96 frozen Dolly validation examples answer-only CE/perplexity at each α. Fix three constraints *before measurement*: (i) ≥baseline-dev strict successes −2 questions, (ii) ≤baseline-dev cap384 hit count +2, (iii) Dolly validation CE improvement ≥0.10 nats/token relative to α=0. Among positive α meeting **all** guards, choose α with lowest Dolly CE. If no nonzero α feasible, choose **α=0 (base)** and report *no deployable adapted candidate*. This selection is finalized in `frozen_dev_selection.json` before reading the 101 IFEval final-test prompts.

**One-time final 101 test:** Evaluate selected α and predetermined original base α0 / original full α1 on **exactly the same 101 unseen IFEval instructions**, same 384 output cap and official rules, with stratified paired uncertainty. If selected equals a control, deduplicate the actual generator calls. Do not select/rerank from test or claim deployment success on an insignificant result. Record all official instruction-family failures, cap hits, output length and comparison; reject if final selected strict accuracy falls below base by more than an independently reported exploratory interval. Testing this system does not itself constitute a novel trained algorithm or end-to-end instruction recovery.

**Engineering and provenance:** One RTX4090 Laptop 16GiB, Qwen3-8B BF16 compute NF4 and frozen rank16 Q/V adapter. GPU-lock and pinned detached worktree with preflight checks, output no-overwrite, fail on source/checkpoint SHA divergence. Real run has up to 5×43 dev plus 3×101 final generations and 5×96 Dolly validation forward passes. All IFEval/Dolly sources and original hashes preserved, failures not silently omitted. Single-model seed, public test content potentially pretrained, heuristic official checker and response truncation are material limitations.
